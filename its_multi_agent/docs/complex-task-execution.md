# 复杂任务执行

核对日期：2026-09-17。面试说明见 [最新项目指南](../../artifacts/interview/ITS_项目介绍与面试指南_2026-09-17.md)。

在聊天端选择“计划执行”，或输入匹配 `needs_plan()` 的“分步执行……”及“先……再……”等请求，会触发复杂任务流程。
模型配置仍沿用当前会话选择。普通聊天沿用原来的路由和回答链路。

流程：规划专家生成 TaskPlan → 代码校验能力和依赖 → 逐步执行 → 步骤验收 → 主 Agent 汇总。
每个计划最多六步。执行者包括资料核实、技术与分析专家、位置与出行专家，以及显式启用后的工程修改专家。
资料核实继续经过 GroundingWorkflow；技术专家只能使用交接的资料和已审查来源。
位置任务沿用原服务 Agent；规划专家不执行工具。Fork 服务分支会注入当前请求的地图 MCP 权限视图。

代码拒绝未知执行者、循环/前向依赖、重复步骤编号和禁用的位置服务；工程步骤需要请求显式启用插件、服务端配置代码根目录及相应工具可用。
用户禁止联网时，执行器移除 search_web，且向资料步骤保留禁止联网的条件。
每步执行调用最多100秒，后续验收另有30秒请求上限，不属于同一个100秒预算。受阻或失败步骤的依赖不会继续执行。
默认按依赖顺序执行；启用 Fork 并行开关时，互不依赖的资料/服务步骤可并行，工程步骤仍串行。独立步骤仍可继续，最终结果区分完成和未完成。不会自动修改用户目标或无限重规划。

SSE增加 sagegpt/plan：run_id、status、steps。steps带id、title、executor、status、detail。规划完成后，独立的资料/服务 Fork 分支可按依赖层并行执行；工程分支保持串行以保护共享工作区。每个执行波次完成后发送快照，依赖步骤只在前置步骤验收通过后启动。
前端同一run_id更新一张进度卡。断流或取消会把未结束的卡片标记为中断。
后端 TaskManager 保存任务事件和计划快照，PlanExecutor 还在每个执行波次后保存独立的步骤 checkpoint，后台执行与连接分离，断流不会自动取消任务。失败或取消的任务可通过
`POST /api/tasks/{run_id}/resume` 显式恢复；恢复前校验请求身份、工作区、插件确认、模型配置和
checkpoint 版本，并跳过已验收步骤。未完成步骤包含服务或编码执行器时会拒绝恢复，避免重复可能有副作用
的操作。前端尚未接入任务接口自动恢复进度卡，最终答案和引用仍沿用会话归档。
进程重启后仅自动恢复排队任务，已运行任务标记失败；用户可以对具备安全 checkpoint 的失败任务显式调用恢复接口。保存快照不代表所有执行器都能续跑：未完成的服务和编码步骤会被拒绝恢复。计划可以部分完成而最终回答流正常结束，应分别查看计划步骤状态与后台请求终态。
步骤验收包含字段/来源校验及模型对交付要求的检查，不等同于所有事实已由独立程序证明。

验证：应用 unittest、前端 npm run check，以及可选真实模型测试：

    python -X utf8 -m its_multi_agent.harness.smoke_complex_task

真实模型测试通过本地FastAPI测试客户端调用聊天接口，隔离身份和历史存储，实际请求模型。
地图和搜索仍依赖已有外部服务凭据；搜索401不会通过新规划流程得到修复。
