# 聊天附件提取

聊天端文档解析现在与知识库提取策略保持一致：先读取可编辑文本和表格，再补充 DOCX XML 文本框、页眉页脚和文档内图片 OCR；内容去重后合并，图片 OCR 会以“图片 OCR”标记。原始附件仍按用户和附件 ID 隔离保存。

聊天 API 优先使用系统 Tesseract（中文模型 `chi_sim` 与英文 `eng`）。可通过 `TESSERACT_CMD` 指定可执行文件，通过 `TESSERACT_LANG` 指定语言。当前 Windows 环境若未配置变量，会自动尝试常见安装位置和项目机器上的 Tesseract 路径。没有可用 OCR 引擎时，普通正文、表格和 XML 文本框仍可提取；只有图片文字会缺失。

支持范围仍受附件大小 10 MB 和单次上下文字符预算限制；扫描 PDF 的页面 OCR 由知识库服务处理，聊天端 PDF 保留现有文本提取逻辑。
