## 部署与迁移边界

- 本次没有调用真实 LLM、Milvus 或地图服务，也没有启动 Docker 做端到端验证。预览通过接口契约与前端构建验证，仍需部署后的浏览器动画烟测。
- SQLite 租约、事件和工程写锁适用于同一主机共享持久存储的进程。多个主机各自使用独立 SQLite 文件不构成分布式协调；外部工具已提交的副作用不能通过取消撤销，也不承诺任意外部工具 exactly-once。
- 旧固定 Milvus 集合无法在原位置增加动态元数据能力。完整迁移步骤见 `backend/knowledge/README.md`：备份后创建新集合，并使用独立注册表和词法索引重新入库，核对后切换；不要直接删除旧集合。
- 现有本地生成文件仍在原目录；Compose 新目录保证后续容器产物持久化。迁移已有产物时需同时保留文件和各自的 metadata.json。
- HTML 预览凭证有效期为 5 分钟，依赖正常配置的 AUTH_JWT_SECRET；过期后重新打开预览。自包含 HTML 可执行动画，外部资源访问被禁止。
- Harness 的来源类别覆盖与关键词匹配是契约指标，不能包装成实际语义正确率。SSE 未提供副作用提交审计时，重复副作用率为未测量。

## 上传操作

本次保留工作树中的既有修改，没有执行 Git 暂存、提交或推送。

在仓库根目录检查当前源文件：

```powershell
python -X utf8 its_multi_agent/scripts/check_secrets.py --worktree
git -c core.safecrlf=false diff --check
git status --short
```

选择需要提交的源代码与文档。暂存后再执行不带 `--worktree` 的密钥检查，
并用 `git diff --cached --name-only` 核对实际提交文件。
密钥扫描不覆盖 Git 历史和所有凭据格式；本记录不是生产部署验收报告。
