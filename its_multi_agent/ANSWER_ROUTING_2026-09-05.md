# 查询决策与证据检查

本次改动作用于主聊天链路，不修改 Docker 或部署配置。

## 实际流程

1. `answer_routing.py` 先处理明确规则：内部资料优先于时效词，实时公开信息查网络，附件优先读取已有内容。来源不明确、追问或混合需求交给所选模型输出结构化计划。
2. 程序校验计划：禁止违反“不要联网”，检查型号、版本、数值和否定/比较条件。混合需求拆成知识问题与公开问题，带内部或附件标记的查询不能直接发往公网。
3. `grounding_workflow.py` 根据可用插件先取证，再检查原文中的标识与引用。无结果或缺少指定型号时直接停止；已有证据再交给无工具的结构化审查模型，判断主体、适用条件、时点、覆盖范围和冲突。
4. 证据不足或冲突时保存并返回说明；服务失败与引用检查失败使用错误结束状态。审查通过后，回答模型收到原文和来源编号，该轮不能再自行切换知识库/搜索工具；仍可按组合需求使用地图与服务站工具。
5. 只有计划明确允许的公开知识问题，才会在知识证据不足后补查一次公网。私域事实不能通过公网补查替代。

附件中的可提取文字也参与证据检查；图片继续使用现有视觉模型流程，不在这轮文字证据审查的覆盖范围内。附件与公开政策对比使用附件原文和单独的公开查询。

## 性能与边界

- 明确规则不额外调用路由模型。需要语义规划的问题增加一次结构化调用；有候选证据时增加一次审查调用。公开补查至多一次，无循环自动搜索。
- 单次规划/审查超时 30 秒，单次检索超时 45 秒。取消请求会取消当前等待。结构化输出需要所选供应商支持相应 JSON schema 能力，失败时明确报错。
- 每类来源最多取 8 条，每条最多 6000 字符，总计最多 24000 字符；混合审查最多 8 条。截断会显式标记，可能保守拒答。
- 显式来源边界与标识检查由代码执行；开放式语义分类、适用性和冲突判断仍依赖模型。规则不是通用敏感信息检测器，也不是语义等价证明。
- 最终文本仍由模型生成；正确引用某个来源编号不保证每句话都被该来源支持，需要真实问题和人工复核。
- 独立知识库 API 的原有调用方式保留，本次检查接入的是主聊天入口。

## 评测

`backend/app/tests/fixtures/answer_scenarios.json` 包含 28 个人工编写的合成业务场景及示例证据：内部最新制度、公开政策、型号与版本、追问、附件、混合需求、冲突、缺失依据、禁用联网及普通写作等。这些材料不是客户真实数据。

从项目根目录运行离线规则检查，不调用外部服务：

```powershell
& 'its_multi_agent/backend/app/.venv/Scripts/python.exe' -m its_multi_agent.backend.app.services.answer_evaluation
```

真实运行结果另存为 JSON 数组，再评测。`route` 记录最终实际来源，`action` 使用 `answer`、`abstain` 或 `error`；澄清、证据不足和冲突对应 `abstain`，服务错误不能当作正确拒答。`retrieved_source_ids` 记录实际检索返回的来源，不能使用标准答案中的来源填充。

```json
[
  {
    "id": "private-latest",
    "route": "knowledge",
    "action": "answer",
    "retrieved_source_ids": ["travel-2026"],
    "answer": "住宿每晚不超过 500 元，须提供发票。[travel-2026]"
  }
]
```

上面只是格式示例，不是已运行结果。迁移到真实资料时，应将题集中的合成来源编号替换为实际来源编号，并重新标注标准答案、可接受来源与是否应拒答。网页和附件来源编号取决于实际 URL 或上传 ID，不能直接沿用示例别名。

```powershell
& 'its_multi_agent/backend/app/.venv/Scripts/python.exe' -m its_multi_agent.backend.app.services.answer_evaluation --cases path/to/business_cases.json --predictions path/to/observed_answers.json
```

报告分别给出：预测覆盖率、路由准确率、回答/拒答动作准确率、证据召回率、引用来源匹配率、答案关键内容覆盖率及各自分母。缺失预测计入相应失败，重复或未知题目 ID 会被拒绝。关键词命中和引用编号匹配都是辅助指标，不代表答案语义正确率。

本轮未调用付费模型生成实测答案。先前本地 Milvus 连接失败的限制仍在，未将其作为本轮部署任务处理。

## 本轮验证结果

- 主后端 105 项测试通过，包括 43 项新增测试；知识库后端 44 项测试通过。
- 28 个业务场景规则检查通过，其中 9 个明确交给语义规划，未将它们算作模型分类正确。
- 真实 Agents SDK 配合本地模型替身验证结构化规划和审查，确认这两个阶段没有可调用工具。
- 聊天集成测试验证证据不足时不生成答案、说明正常归档、原文不写入会话档案、答案阶段的工具范围受限。
- 本地后端已刷新；没有进行付费模型端到端评测或本次前端改动。
